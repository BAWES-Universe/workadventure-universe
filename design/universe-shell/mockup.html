    What the shell changes

      Shell principles this mockup assumes

      1. Surfaces, not components. Chat, cameras, co-websites, Orbit, cards and modals register with one shell as surfaces with a size, a minimum, and the moves they allow (dock, float, pop out, full).
      2. The map is a surface too. It can shrink to a peek window and come back. The Phaser camera reads the shell's free rectangle instead of scanning the DOM for .screen-blocker.
      3. One layer order. A registry replaces the twenty hard-coded z-indexes: map, docks, floating, sheets, modal, system, toast.
      4. Phones get sheets and strips. Bottom sheets with snap points (peek, tall, full) and a video strip that can sit at the top, the bottom, or collapse into bubbles.
      5. Desktop gets docks and windows. Left, right, top, bottom docks, floating windows, and true pop-outs through the Document Picture-in-Picture API the camera code already uses.
      6. Every existing hook keeps working. WA.nav.openCoWebSite, WA.ui.modal, WA.ui.website, WA.chat, zone properties and extension modules map onto shell intents; the shell adds a layout API instead of replacing them.
      7. Presets, then freedom. Named layouts (Hangout, Meeting, Studio, Focus) cover most people; dragging a surface to another dock is for the rest, and is remembered per device class.
      8. Nothing is removed. Same rule as the Chat and Express epic: any surface or action that exists today has a home in the shell.
